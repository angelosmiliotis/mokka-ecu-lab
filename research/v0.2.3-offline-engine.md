# v0.2.3 documented correction and local evidence research

## Sources and correction

The [SAE edition catalog](https://saemobilus.sae.org/standards/j1979da_201110-j1979-da-digital-annex-e-e-diagnostic-test-modes) identifies J1979-DA OCT2011. The original [consulted annex](https://www.e90post.com/forums/attachment.php?attachmentid=1509324&d=1476497126) was inspected as text and rendered pages: B115 pp.82–84 and B102 p.71. No PDF, image, table reproduction or private vehicle payload is distributed.

The previous project incorrectly attributed a three-byte SCR layout to OCT2011. B115 covers A–M (13 data bytes). A provides current activation and four current reasons, with reserved bits 4–6 zero and all current bits zero when inactive. B/C latch four rolling history blocks; historical reasons can remain set after current activation ends. D/E, F/G, H/I, J/K and L/M are unsigned big-endian kilometre counters: current active distance, current total distance, and active distances in three older blocks. The five counters are not distance since regeneration or a health score.

The encoded range is 0–65535, with no specified missing-value sentinel. The block algorithm rolls at 10000 km and retains history across ordinary code clearing/battery disconnect; it is not an absolute odometer timeline. Encoded values above the nominal block size or a current numerator exceeding its denominator produce explicit semantic warnings, without clipping or treating 65535 as unavailable. Temporal rollover/physical accuracy cannot be verified from one sample.

The [supporting DashLogic listing](https://www.dashlogic.com/docs/technical/obdii_pids) agrees on the A–M shape and flag locations. Its repeated B/C labels in the later distance formulas are inconsistent with its own D–M byte rows; they were not copied. The primary byte pairs drive the implementation. This listing also contains previously documented PM-unit and warning-counter text inconsistencies; it does not override the primary annex.

B102 still specifies seven bytes including field-support byte A. Six-byte 017A cannot be normalized by inserting/removing a byte, interpreted as signed pressure, or used to infer blockage/condition. Exact ECU hardware/software/calibration applicability remains unknown. Published formula, vehicle-observed response and independent measurement verification remain separate dimensions.

## Local workflow

Research contains **Knowledge & provenance**, **Offline evidence analyzer**, and **EXPERIMENTAL hypotheses**. Import 1–16 existing local Research Bundle ZIPs. All root-level member checksums must match; duplicate/path members, encrypted/oversized inputs and incomplete checksum coverage fail closed. Nothing is extracted or uploaded. Eleven-file legacy and twelve-file current bundles are supported. Limits: 64 MiB/member, 128 MiB decompressed total, 250000 journal lines/session, 128 source groups/session, 2000 raw candidate samples/group for UI preview; aggregate counts cover the entire bounded journal. Duplicate evidence selection is rejected.

Compatibility reports separate session, ECU, mode and source. They reparse wire framing, negatives, support bitmaps, payload lengths, field support, layout mismatches and byte changes. Support snapshots are shown independently: absent original bitmap evidence stays UNKNOWN, and contradictions are reported. Re-decoding uses the current definitions; old CSV values, raw journals and recorded decoder versions remain intact. RAW-only provenance remains visible even where a documented offline interpretation now exists.

For 017A, select byte A–G for a scatter plot against session-relative seconds. A byte missing in a six-byte payload has no plotted value. The byte table and detailed findings include cached RPM, MAF and speed, source timestamps and age. They use prior samples from the same session/ECU/mode/source only, without interpolation, additional requests or simultaneous-value claims. Missing context stays UNAVAILABLE. Correlation does not prove a decoder. Detailed local JSON outputs contain private operational evidence and must not be committed/shared as anonymous sensor definitions.

Headless Python or packaged Windows analysis uses:

```powershell
python -m mokka_ecu_lab --analyze-bundles "C:\private\existing-bundle.zip" --research-output "C:\private\analysis.json"
```

This branch starts no GUI or transport. Use a separate JSON output; originals cannot be overwritten. The Windows executable accepts the same arguments.

The versioned JSON knowledge base is stored at `<data-dir>/research/catalog.json`, outside the application source/release folder in normal use. It starts with a provisional Opel Mokka 2022 diesel profile and UNKNOWN engine/ECU hardware/software/calibration identity. Local evidence summaries store exact source ECU, per-ECU supported PIDs, lengths, checksummed evidence identity and import provenance. Published definitions record field formulas, units, signedness, flags, sentinel rules, source edition/table, verification state and synthetic-test provenance. Import time is not independent verification time. Definitions are code-owned and cannot be changed into live permissions by catalog edits.

Offline hypotheses use an explicit byte slice, byte order, signedness, scale/offset and optional same-condition reference values. **Save report** retains the candidate in the local catalog as EXPERIMENTAL. Rejection can be recorded; no promotion to INDEPENDENTLY_VERIFIED or dashboard decoder is provided. The future definition-only `contribution-v1.schema.json` excludes raw recordings, route history, source ECU IDs and vehicle identifiers. It requires independent source/method/test metadata and human privacy review before any eventual contribution. No account, contribution uploader, cloud sync or remote backend is implemented.

## Future recording requirements

No extra road test is required to develop/use this release offline. For an eventual explicitly chosen consolidated vehicle session, keep the existing stationary Discovery/recording workflow and unchanged 4 req/s total:

1. Retain original complete 017A responses in optional RAW-only mode; do not alter bytes. Record RPM, MAF and speed in the same journal. Context remains asynchronous, with age and gaps.
2. Select documented 0188 numeric monitoring manually when per-ECU Discovery validates all 13 bytes, or select 0188 RAW-only for diagnostic capture. Current flags, latched history and all five distance counters need separate interpretation. Neither option is preset by default.
3. Keep NOx 0183 as an explicit manual opt-in and existing 0185 capture. A single NOx reading, static warning-time counter or quantized tank variation is not a trend/fault/consumption measurement.
4. Obtain independent reference readings with timestamps, units, uncertainty and independently known calibration identity before evaluating pressure hypotheses or claiming vehicle verification. Do not clear codes, force inducement/regeneration or request new ECU identifiers to obtain evidence.

D525/D526/D52F/D532 stay offline candidates. A shared engine/manufacturer/ECU family does not prove proprietary DID compatibility. No physical ECU/DPF validation claim is made.
