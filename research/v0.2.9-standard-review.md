The consulted primary edition is [SAE J1979-DA OCT2011](https://saemobilus.sae.org/standards/j1979da_201110-j1979-da-digital-annex-e-e-diagnostic-test-modes). A previously saved reference copy was read locally; no PDF/table images are distributed. Functional definitions are implemented in code with strict lengths and field flags. Primary edition review does not prove exact-vehicle accuracy or applicability of another revision.

The staged process separates pure decoder definitions/synthetic tests from the code-owned read-only transport scope. Editing the knowledge catalog or opening a report cannot grant requests. The v0.2.9 reviewed scope contains 23 additions; no arbitrary advertised PID, Mode 22, UDS, reset, actuation, coding, security or forced-regeneration command is admitted.

The complete primary field layout of `0101` is recognized as an ignition-dependent readiness/status item; implementation is deferred rather than exposing partial readiness as a verified monitor result. `019D` was not defined in the consulted edition, so its meaning, length and formula remain UNKNOWN. Neither request is enabled. Other speculative OEM leads retain the existing offline-only records.

Reported PM-sensor regeneration (018F) and hybrid fuel-type encoding (0151) are distinct from DPF regeneration. MIL-related accumulated counters are historical observations. VGT fault-coded data is unavailable, not a validated vane position. Rounded historical 018C scaling is explicitly edition-specific; no sentinel or physical calibration is invented. Existing six-byte 017A receives no numeric pressure decoder.

The [structured definitions](../mokka_ecu_lab/sensors/extended.py) retain table, layout, units, formula, flags, enum-unavailable codes, edition and limitations. Independent formula/framing/negative/malformed tests live in [test_standard_extension.py](../tests/test_standard_extension.py); lifecycle, budget, recovery and report tests verify integration.
