# Layout verification boundary (corrected in v0.2.3)

This public note contains generic layout shapes and implementation rules only. Private recordings, route statistics, session identifiers, timelines and the supplied analysis are excluded. All distributed test payloads are constructed and non-identifying.

| Request | Documented numeric layout retained | Alternative shape exercised synthetically | Numeric interpretation of alternative |
|---|---|---|---|
| 017A | OCT2011 B102, 7 data bytes including field support | 6 data bytes, ISO-TP payload length 8 | None; do not remove a flag byte or assume the same scaling |
| 0183 | OCT2011 B110, 9 data bytes with individual field support | No new layout accepted | Existing supported-field decoder only; opt-in trend capture |
| 0185 | OCT2011 B112, 10 data bytes | No new layout accepted | Existing four fields and validation unchanged |
| 0188 | OCT2011 B115, 13 data bytes, ISO-TP payload length 15 | Three-byte or other length | No numeric interpretation of unknown lengths; optional RAW-only also bypasses documented decoding |

The earlier claim that OCT2011 B115 specified three bytes was incorrect. v0.2.3 inspected the original [annex copy](https://www.e90post.com/forums/attachment.php?attachmentid=1509324&d=1476497126), pages 82–84, and corrected 0188 to 13 bytes. A newer edition is not needed to explain this length. B102 page 71 still specifies seven bytes for 017A; the six-byte variant has no authoritative numeric definition. No copyrighted tables or pages are distributed. See [technical semantics](v0.2.3-offline-engine.md).

RAW-only accepts complete positive responses for fixed 017A/0188 after completed explicit discovery and the selected ECU's own advertised support. It bypasses numeric outputs even when a response matches the historical layout. Framing validity, complete data length, service-inclusive ISO-TP payload length, documented length/edition/table and separate layout status remain visible. Matching the historical shape does not identify the ECU's implemented revision. Malformed ISO-TP, negatives and transport failures remain errors and retain the three-failure/reconnect boundary; no retry is added. Numeric Discovery layout mismatches remain INVALID with category DECODER_LAYOUT, distinct from malformed frames.

Future numeric acceptance requires an authoritative exact revision/table or OEM technical definition; unambiguous byte order, flags, signedness, scale, units, sentinel definitions and semantics; independently identified applicable ECU/software context; a second independent controlled stationary instrument comparison; and regressions for accepted/rejected shapes. Source review and independent measurement must precede VEHICLE_VERIFIED. Until then, no pressure, soot/ash/health percentage or current SCR state is inferred from an alternative shape.

For later user-controlled stationary validation, select only advertised candidates after Discovery, opt into RAW-only, include RPM/speed and NOx when available, retain the global cap, then Finish session and Disconnect. Cached RPM/speed includes its own acquisition time and age; it is not simultaneous, interpolated or an extra query. Prepare longer captures while parked; a passenger operates the GUI. Do not induce regeneration or probe unknown PIDs.

0185 warning-mode engine time is a counter. Static/nonzero values alone prove neither a current warning/fault nor a clean SCR system. Tank quantization/change is not measured fluid consumption. 0183 fields remain individually gated by support bits; a single sample cannot establish a trend. Recorded plots separate ECU/mode/source, use elapsed time and unjoined points, and never pair independent peaks or interpolate gaps.

D525/D526/D52F/D532 remain offline candidates. No OEM live read, UDS session, arbitrary header, security access, write/reset/clear/coding/adaptation or regeneration routine is authorized.
