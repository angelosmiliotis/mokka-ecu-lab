# v0.2.11 evidence and research boundaries

This public note contains no vehicle logs, original hashes, private chronology or derived vehicle measurements. Public examples are constructed. Formula agreement with stored CSV is software consistency, not independent physical calibration.

## Serial lifecycle

Microsoft defines Windows error 121 as a semaphore timeout. An error opening a COM port before any send cannot establish ECU overload. OS pairing, an open Windows handle, adapter initialization and current positive ECU evidence are distinct. Successful idle reuse avoids a needless close/reopen, but it does not prove the Bluetooth failure's root cause. Driver/power state, a competing owner or link availability remain hypotheses requiring a controlled field test. Generic vendor guidance distinguishes pairing and connection; it does not diagnose a specific recording. See [Microsoft system errors](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-) and [OBDLink connection troubleshooting](https://support.obdlink.com/support/solutions/articles/43000715570-troubleshoot-connection-issues).

## Inventory, cadence and sensor interpretation

Bounded Benchmark preflight reads only early continuation pages needed by its fixed subset. Offline inventory labels that PARTIAL, records unread advertised pages and does not interpret missing later support evidence as lost ECU features. A Comprehensive session follows the full advertised chain. Counts of numeric field IDs are not counts of independent physical sensors. Per-field cadence/age and flag state determine useful temporal coverage; the critical subset's software scheduling advantage needs a matched real drive before a physical comparison.

The six-byte `017A` reply remains RAW-only. Integer endianness, observed spacing and stationary/moving/thermal groups are descriptive hypotheses. Offline correlation reports expose prior-sample age, stale NULL values and 1/2/5/12-second age sensitivity. Dependent serial samples, temperature, flow, load and calibration confound interpretations. No pressure, soot, ash, DPF health or regeneration decoder is selected.

`018C` layouts outside the exact reviewed definition remain blocked; no padding, truncation or invented values. SAE's [J1979DA revision catalog](https://saemobilus.sae.org/standards/j1979da_202305-j1979-da-digital-annex-e-e-diagnostic-test-modes) establishes revisions, not an accessible exact applicable byte definition for the observed unknown layout. A primary applicable definition and controlled tests are still required. `0101` and `019D` remain outside LIVE. No new sensor command is enabled by this release.

`010B` byte 255 can censor the encoded MAP range. The current valid same-context `014F` selector determines scaling; `0150` applies to MAF. Clipped MAP cannot reconstruct higher boost. Exhaust pressure is not a substitute for manifold pressure. No currently verified alternative is inferred from an advertised bit alone. Same-frame VGT position minus command is descriptive, not a lag/fault diagnosis. Pedal D/E, throttle and EGR command/error are different fields. Quantized reagent level is not consumption; current and historical SCR inducement differ. PM-sensor regeneration is distinct from DPF regeneration. Sport timing requires a human annotation with uncertainty; acceleration alone is insufficient.

## Future rate research — locked OFF

The physical ceiling stays **4 total send starts/s** across setup, reconnect, normal sessions and benchmarks. The pure `future_benchmark` arithmetic model sends zero requests and has no transport import. Its illustrative 4/5/6 values are assumptions, not authorized settings or a sustainable-capacity estimate. Baud rate is not request throughput.

A future separately authorized parked-only protocol could review adapter/vendor limits, repeat matched four-request baselines, then consider at most a few discrete steps such as five and six with the identical allowlisted PID mix. It would require bounded duration, explicit each-run start, immediate Stop, fresh support, adequate ventilation, no competing client and no automatic ramp/retry. Track actual spacing, end-to-end latency distributions, timeout/NRC/COM errors, UI responsiveness and unknown thermal conditions. End-to-end latency does not measure CAN load or ECU capacity. A clean short fixed-subset run cannot validate all-sensor drives or justify ten to twenty requests/s.
