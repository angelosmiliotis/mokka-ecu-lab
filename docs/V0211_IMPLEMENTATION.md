# v0.2.11 implementation and acceptance plan

Base: published v0.2.10. All supplied originals and derived reviews remain in a private directory outside Git. No real migrations, moves, cleanup or installation replacement are authorized by this development task; the delivered preview must identify exact paths before any later approval.

1. **Connection lifecycle:** keep a verified successful Benchmark connection open and idle by default; explicitly selectable disconnect. Reuse only matching source/port/context with fresh recorded preflight. All stop/error/shutdown/suspend/removal paths close. Clear measurement deadlines before any reuse. Reconcile the normal Session coordinator so Connect/Start remains usable. Distinguish COM-open failure from adapter/ECU/preflight/measurement failures.
2. **Private library:** additive storage module and local index. New exports use one immutable run directory with original ZIP, JSON/HTML and hash metadata; existing journals/database remain untouched for compatibility. Atomic staging/verification and recoverable PARTIAL state. History filtering, display labels, private wrapper export/import, annotations and checksum-based duplicate detection. Legacy migration is preview plus explicitly confirmed copy, retaining originals; interruption/resume is idempotent. No delete/move implementation is needed to provide a safe migration.
3. **Managed versions:** explicitly chosen install root, trusted release SHA and package validation, new copy-only staging, smoke validation, current/previous pointers with rollback. Dry-run inventory and provenance expose unmanaged or changed files. Never delete personal data or old builds; no recursive cleanup or broad filesystem scan. A running executable is never overwritten.
4. **Offline evidence:** independently verify all original files, reproduce the old reports before schema changes, rederive every numeric row, field distribution and RAW-context alignment. Label partial bitmap discovery, serial-open failures, unavailable layouts and MAP censoring accurately. Keep >4 req/s entirely in a pure synthetic feasibility model/design, with no transport switch or bypass.
5. **Release gates:** synthetic regression tests, fake LIVE serial sequential benchmarks and failure injection, one-worker aggregate spacing, compatible old/new bundle readers, atomic/resumable copy, managed rollback/lock tests, native 100/125/150% inspection and packaged normal/critical/sequential/library/version flows. Source/executable offline parity and private replay preserve original hashes. Publish only after privacy/tree/tag/asset verification.

Acceptance includes connected idle with zero traffic between explicit runs; fresh preflight for each run; no retained operation deadline; deterministic resource closure; accurate zero-send COM failures; one folder per run with valid companions; no overwrite, source move or deletion; no unverified numeric decoder; unchanged allowlist and physical 4 aggregate req/s ceiling. Independent physical v0.2.11 validation remains pending until new field recordings.
